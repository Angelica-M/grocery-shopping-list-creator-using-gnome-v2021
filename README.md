# Grocery Shopping List Creator
A GUI program using C++, Linux, &amp; the Gnome Library that lets users create custom recipes and add items to their shopping list in-bulk based on a recipe or individually.

<img src='https://github.com/Angelica-M/Grocery_Shopping_List_Creator/blob/main/GG_Demo_0.JPG' width=''/>

To run this program in Linux enter the following into the terminal:

```
cd GG
make 
./gg
```

## Topics Demonstrated

### Desktop UI Engineering & Native Runtimes
* **native-desktop-development** — Compiled standalone software binaries optimized to run directly on local host hardware layers.
* **gui-library-orchestration** — Utilized the GNOME toolkit API to programmatically draw, manage, and coordinate desktop window component objects.
* **event-driven-architecture** — Implemented signaling mechanisms and callback handlers to trigger dataset changes upon user UI interactions.
* **desktop-window-management** — Engineered window frame lifecycles, surface rendering, and application view scopes natively within a Linux windowing system.

### Data Engineering & Structural Algorithms
* **data-structure-engineering** — Designed explicit, multi-tier data structures to cleanly isolate and model recipes vs. flat shopping list arrays.
* **bulk-data-processing** — Engineered batch execution loops that read a complex recipe schema and map all underlying elements into a collection instantly.
* **relational-data-handling** — Constructed data relationships where individual shopping items map back structurally to parent recipe categories.
* **vector-manipulation** — Executed memory-managed array insertions, index updates, and deletions within native C++ sequential containers.

### Systems Programming & Compilation Governance
* **systems-programming** — Wrote compiled, type-safe code that interacted natively with local desktop environments and operating systems.
* **compilation-governance** — Managed source code compilation topologies and build targets using explicit Makefile build automation scripts.
* **gnu-make-automation** — Designed declarative dependency rule graphs to automate compiler flag routing and binary linker execution phases.
* **memory-management** — Adhered to strict native C++ object scoping, stack management, and data lifecycle boundary rules.

### Software Engineering Design & Lifecycle Gates
* **decoupled-architecture** — Separated the UI presentation layout nodes from the internal recipe calculation and list storage engines.
* **software-integration** — Programmatically aligned standard C++ collections with native Linux shell routines and external C-based GNOME layouts.
* **systems-validation** — Tested cross-component operations to ensure bulk-inserted recipe arrays updated shopping lists without memory or index faults.
* **deterministic-state-control** — Designed a closed local logic system where the visible list layout perfectly reflected internal application vectors.

### Linux Environments & Computing Foundations
* **linux-subsystem-utilization** — Deployed code paths optimized to run within a POSIX-compliant terminal and desktop environment.
* **cli-execution-orchestration** — Structured explicit terminal invocation routines to handle navigation, building, and application startup safely.
* **object-oriented-programming** — Utilized strict class encapsulation, inheritance rules, and type accessors to format internal data structures.
* **data-mutation-safeguards** — Implemented logic gates that allowed items to be added individually or via batch operations without state drift.
